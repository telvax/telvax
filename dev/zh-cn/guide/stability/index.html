This is the documentation of the development version (the main branch). It can describe things that are not released yet.

语法稳定性

今天能运行的程序，以后仍然能运行。语法按版本（edition）分组。到目前为止只有一个版本，即 2026，它的语法已经冻结： 从包含本页的这个发布版起，用 2026 版写成的程序，会被之后所有能读取 2026 版的 Telvax 接受。

承诺了什么

Section titled “承诺了什么”
  • 不会破坏程序。 tests/editions/2026/ 中的每个程序都必须继续通过 telvax check、telvax fmt --check，并且在含有 test_... 函数时通过 telvax test。运行这些检查的测试是 cli/tests/editions.rs。
  • 文件是冻结的。 tests/editions/2026/CHECKSUMS 保存了每个程序的哈希值。修改某个程序， 或者新增程序却没有对应的行，测试都会失败。必须修改冻结程序的 pull request 属于不兼容的改动， 需要新的版本（见下文）。
  • 可以新增语法。 新增一个词、一种形式或一个标准库函数，只要不会让任何旧程序失效，就是普通的 feat: 改动。 新程序也会放进冻结的目录，所以这个承诺的范围会不断扩大。
  • 错误信息不在承诺之内。 诊断信息的文字、lint 警告，以及 telvax fmt 对格式化器以前会拒绝的代码的输出都可能改变。 格式化器不会改变已经格式化好的程序的排版。

没有承诺什么

Section titled “没有承诺什么”
  • std 库可以增加函数，一个函数也可以增加新的重载。删除或修改函数， 遵循与语法相同的规则：需要新的版本。
  • 原生后端、GPU 执行和加速器输出列在 docs/design/status.md 中； 能在那里运行的程序会越来越多，原来不能原生编译的程序也可能变得可以编译。
  • 修复 bug 可能会拒绝只因为这个 bug 才能运行的程序（比如检查器漏掉的类型错误）。 这样的改动会写在 CHANGELOG.md 中。

选择版本

Section titled “选择版本”

telvax.toml 指定一个包使用的版本：

  • 没有这一行时，包按编译器已知的最新版本读取。 tvpm new 会写入这一行，所以新包从一开始就是固定版本的。
  • 编译器不认识的版本会报错，错误信息列出它认识的版本，并在包的版本更新时提示升级 Telvax。
  • 没有 telvax.toml 的单个文件按最新版本读取。

新的版本

Section titled “新的版本”

如果一项改动会让旧程序无法编译，或者改变了旧程序的含义，它应当放进新的版本， 而不是已有的版本：

  1. 旧版本仍然像以前一样编译。编译器两个版本都能读取，由 edition 选择。
  2. 新目录 tests/editions/<年份>/ 有自己的冻结程序和 CHECKSUMS，并且年份要加入 tools/package-manager/src/manifest.rs 中的 EDITIONS。
  3. CHANGELOG.md 列出改动内容，telvax-migrate（tools/migrate）增加一条规则，在可以机械完成的地方 把旧源码改写成新版本。
  4. 旧版本再支持多久，在提出第二个版本时决定；停止支持某个版本 本身是一次单独的 feat!: 改动。

目前已有的内容

Section titled “目前已有的内容”

已完成：edition 这一行及其检查、冻结的程序和保护它们的测试，以及本页。尚未完成：第二个版本（因此同时读取两个版本还没有测试过）、 对已弃用形式的警告，以及 telvax 二进制文件内部的 telvax migrate 命令。telvax-migrate 工具负责转换旧的 Rust 风格语法，目前仍是一个独立的程序，之后会被移除。
